# App 集成、Agent 能力与交付需求

状态：2026-10-23 确认的下一步需求基线；不是已完成的部署手册。本文明确产品行为、责任边界和验收结果，配置入口名称、安装命令及实现接口在实施时确定。当前实现与缺口见第 9 节。

本文是 App 团队集成 AiricForge 的主入口。[CertLab 接入](certlab-integration.md)说明当前实例的具体协议；[集成 Skill](../skills/airic-app-integration/SKILL.md)指导开发 Agent 按本需求实施。当前实现和后续需求分别标注，接入以当前契约为准。

## 1. 产品目标与范围

App 团队将 Forge 作为有明确版本的第三方服务，组装进 App 的运行环境。最终用户在 App 中使用 Copilot，组织通过 Forge 管理和改进业务 Operating Model。使用方无需复制 Forge 源码或重新组装 Pi 对话循环，才能获得基本执行能力。

交付闭环是：确定业务任务 → 发布 App MCP → 配置基础 Agent 能力 → 本地联调 → 初始化组织 OM → 在 App 中工作 → 基于轨迹改进 OM → 发布软件新版本 → 升级、备份和恢复。

本轮保持一个 Forge 实例连接一个业务 App 和一个组织的范围。开发时允许从本地 Forge 源码运行；这不改变发布时的第三方组件边界。不引入多 App 平台、插件市场、新 Agent 框架、新 PDF 引擎或 OCR。

## 2. 能力与事实的所有者

| 所有者 | 负责 | 例子 |
| --- | --- | --- |
| 基础 Agent 与能力包 | 通用文件理解、分块阅读、图文选择、检索、工作笔记、压缩和恢复；复用 Pi 会话、工具、Skills、扩展与包管理 | 大型 PDF 定位、局部放大、覆盖范围记录、恢复后接续 |
| 业务 App | 身份、业务事实、业务授权、查询与命令、事务、版本、原始回执；提供资料和页面状态 | CertLab 资料分页与图像接口、条款上下文、保存评估草稿 |
| Forge | Work 绑定、固定 OM 修订与执行来源、业务桥、检查点、轨迹、Reflection 与 OM 治理 | 原命令结果核对、个人提交、组织贡献与采纳 |
| 组织 OM | 组织特有的业务逻辑、专业判断方法、职责与交接要求 | 什么证据足以支持条款判断、标准例外、复核责任 |
| App 集成与交付配置 | 选择上述软件和能力版本，连接服务，准备依赖 | Pi settings、扩展包、部署地址、镜像版本 |

**I-01：通用阅读能力不能依赖组织补写操作流程。** 如何分块理解大型 PDF、何时取文字或页面图像、怎样记录进度及整理后续读，属于基础 Agent 能力。OM 可要求结论有可定位出处、专业证据充分、不能把未知当作不存在，但不包含分页调用顺序、笔记文件名或压缩恢复算法。不能只把一份带认证条款语义的 Skill 改名为通用能力；阅读方法必须在其他领域也可复用。

通用阅读能力可通过 Skill、扩展和 App 文档工具协作提供。App 适配器保留工具参数、身份与返回值映射，通用阅读策略不复制到每个 App 或每份 OM。只有 App 提供资料接口时，才承诺这些资料可被读取。

**I-02：业务能力仍经 App 原用例执行。** MCP 工具目录不是第二份业务规则；Forge 角色、OM、前端状态或模型判断都不能替代 App 专业授权。未知写入结果仍阻止后续业务写入，恢复查询原回执，不能自动重放效果。

## 3. 发布内容、种子与运行状态

**I-03：Agent 配置随 App 代码和发布产物管理，生效 OM 独立演化。**

| 内容 | 管理方式 | 更新方式 |
| --- | --- | --- |
| App、Forge、Pi 及扩展 | 代码、依赖锁定、发布清单和镜像摘要 | 测试后发布 |
| Agent 配置、通用 Skills、本地扩展及系统依赖声明 | App 仓库或受版本控制的能力包 | 开发验证后发布 |
| 初始 OM | 版本化种子，供新组织初始化 | 已有组织通过显式审查获取改进 |
| 组织与用户生效 OM、候选稿、Git 历史 | 持久化 OM 仓库与 Forge 治理 | 运行时提交、审查、采纳和同步 |
| 数据库、原生会话、工作文件、轨迹 | 持久化运行目录 | 工作执行、备份和恢复 |
| 模型和 App 凭据 | 部署 Secret 或现有短期授权机制 | 独立轮换；不进入版本库、配置示例或会话 |

示意目录属于 App 项目，不要求 App 使用固定目录名：

```text
app-project/
  agent/
    settings.json
    packages/
    skills/
  operating-model-seed/
  deploy/
    compose.yml
    forge.Dockerfile
  runtime/                   # 不进 App Git；OM 在其中有自己的 Git 历史
    project/                 # 持久化 OM，不是 agent/settings.json 的位置
    data/                    # 数据库、会话、工作目录与轨迹
```

配置目录只读、运行目录可写是交付契约。仍可沿用 `/project`、`/data` 两个挂载点，不要求为了统一目录而迁移已有运行数据。能力安装缓存是可重建产物，不能混作生效配置或唯一依赖清单。

## 4. Pi 配置与能力装配

**I-04：显式加载部署声明的能力，复用 Pi 原生机制。** Pi `settings.json` 声明 packages、extensions、skills 等资源；扩展包 `package.json` 声明资源和 JavaScript 依赖。复用 Pi 的包解析、资源筛选和加载机制，不增加 Forge 自有插件描述语言或第二套包管理器。

Forge 提供显式 Agent 配置入口，并能区分公共能力与 Work/Reflection 各自可加载的资源。具体路径和选择参数在实现时确定，不预先声称存在某个环境变量。宿主个人目录、Work 文件、OM 或模型生成文件不能隐式改变部署的扩展集合。

版本化 npm/Git 包固定版本或提交；本地资源记录内容身份。JavaScript 传递依赖及系统依赖由构建锁定或记录实际解析结果，不能只凭顶层包名声称可重复部署。本地包的依赖需显式准备；Python、浏览器、系统程序等由开发环境准备步骤和镜像声明提供。配置不能凭空安装系统依赖。

部署准备阶段安装和校验依赖；普通 Turn 不联网安装或更新能力。启动时缺包、缺程序、扩展失败或配置非法，应定位到来源并给出修复方向；不能静默少加载资源仍宣称环境完整。Pi 终端菜单、快捷键和交互窗口不自动等价于 Forge Web UI；需要界面适配的扩展应明确报告支持范围。

扩展是受部署团队信任的可执行代码，不是 OM 内容。当前本地原生工具以进程权限执行，工作目录不是安全沙箱；生产运行身份、可访问文件和网络范围由部署环境落实。Reflection 继续没有 App 业务凭据和业务桥，正式 OM 候选稿经治理工具保存。不能把资源配置筛选宣称成任意插件的操作系统隔离。

## 5. 从空项目到完成一次业务任务

### 5.1 准备业务接入

App 团队先选择一个具体任务，列出必要事实、效果、权限和人工交接点，再映射到现有业务用例。MCP 应提供身份与组织绑定、清楚的工具输入输出、固定来源的资料读取，以及业务命令准备和回执核对。不要为 Agent 另开可绕过 App 规则的写路径。

**I-05：身份、Work 与页面绑定可验证。** 当前用户通过 App 身份验证进入 Forge；报告等对象绑定到正确的 Work，重新打开可以定位既有 Work。页面选择仅用于聚焦，权威上下文由 App 重新读取。Token 失效、用户停用、目标切换和越权时，应明确拒绝并清理相关授权，不混用其他用户的会话。

保持现有 MCP 动态发现与不可变每 Turn 工具快照，不恢复目录人工接受、WD 工具白名单或旧 Manifest/Agent OpenAPI 协议。新 App 需要明确身份、上下文与业务适配；当前 CertLab 绑定代码不能被描述成任意 App 已可零代码接入。

### 5.2 初始化与重复启动

**I-06：新组织初始化、已有环境启动、种子更新是三个不同操作。**

新组织选择固定种子，建立组织 OM、用户基础和必要运行存储，记录种子来源。重复执行不能重复建号、重置分支或覆盖修改；不完整初始化应可诊断和安全恢复。已有环境重启读取持久化状态。发布包附带新版种子，不会自动覆盖已有组织或个人 OM；采用其改进走显式导入、比较和治理流程。

### 5.3 执行、交接和恢复

**I-07：执行来源固定且可接续。** 每次运行可关联组织、用户、Work/Reflection、Turn、OM 修订、工具快照、Agent 配置和实际资源身份、模型配置身份及部署版本。地址和密钥值不直接作为公开指纹内容；记录足以区分执行环境的非秘密身份。

同一环境显式恢复绑定的 Pi 会话；OM、工具、模型或能力配置发生相关变化时，创建新会话关联并保留旧会话和工作文件。新环境从最新业务事实、未决命令及带来源的笔记接续；不能把跨版本笔记视为权威或无条件重读全部资料。会话文件缺失应报告，不能伪造完整恢复。

大型 PDF 阅读应能定位相关范围、按需阅读原文和图像、记录事实/疑点/覆盖/下一步，并在压缩后继续产出。无文字层不等于没有可见文字，索引和摘要不等于原件，也不能据检索未命中推定资料不存在。验收使用真实可读性差异，但不以业务结论必须符合为通过条件。

**I-08：连接、任务和业务结果有不同生命周期。** 保持当前断连取消与撤销短期授权语义；重新打开先验证身份、读取历史、展示中断/未决状态，再由用户继续，不默认成为后台常驻任务。取消和停止服务需处理在途调用，未知写入不能标为无效果。进程重启不自动重放业务命令，也不凭恢复了 Pi 会话就自动恢复业务授权。

用户能区分运行、读取、整理、检查点、取消、失败和实际业务保存结果。UI 可以用投影展示，真实成功必须关联 App 回执。历史、正文和图像的本地持久化是受保护的数据；审计/前端不重复暴露完整原生会话、凭据或私有推理。

### 5.4 组织在运行中学习

**I-09：OM 与软件能力分别改进。** 工程师通过轨迹、Reflection 和用户分支修改专业方法，再按既有治理采用；无需发布镜像。发现缺工具或通用阅读机制有缺陷时，形成软件能力需求，不往 OM 填通用操作补丁，也不能由 Reflection 安装插件或直接改生效配置。

App 升级不擅自更改 active OM；OM 采纳也不改变已固定 Turn 的来源。业务工作与 Reflection 都需要验证资源装配与恢复，但 Reflection 不继承 Work 的业务授权。

## 6. 不经过 Docker build 的开发反馈回路

**I-10：本机源码联调是一等支持的交付方式。** App 仓库应提供可重复的开发入口，支持本地 Forge 源码、App API/MCP 和前端分别启动、连接和停止。首次依赖准备可独立执行；每次修改不要求安装包、构建镜像或重建 OM。

最小反馈回路：

1. 显式选择 Forge 本地 checkout、Agent 配置目录和独立开发数据根，准备锁定依赖。
2. 启动 App、Forge 和前端，检查服务地址、身份、组织绑定、MCP 发现和实际资源加载结果。
3. 修改 App MCP 工具、通用 Skill、扩展或 Forge 源码。
4. 按变化重载资源或重启相关服务；有运行任务时先停止并核对在途业务结果。已启动 Turn 不被半途换配置。
5. 在同一个开发 Work 中继续，验证新版本生效、必要的会话切换、笔记保留和真实草稿回执。
6. 运行确定性回归，再按明确授权用真实模型验收资料理解。

工具元数据更新从下一 Turn 动态发现。Skill/扩展和源码允许通过明确的重载或服务重启生效，不强制要求一切热更新；应显示实际加载版本，避免文件已改、进程仍用旧版本而无法察觉。

本地和发布共享 Agent 配置格式、OM 规则、业务桥、授权与恢复契约，只覆盖地址、凭据来源、路径和运行方式。开发路径覆盖不写回发布配置。可以增量构建被导入的 workspace 包，但不能隐藏“仍使用旧 dist”的前提。

开发数据与真实运行目录分开；自动测试不使用业务数据库。开发入口记录和管理自己启动的进程，端口冲突应定位，不终止不归它管理的服务。停止、再次启动、旧 Work 恢复属于联调验收。

## 7. 构建、升级、回滚与迁移

**I-11：应用发布可复现，并验证与当前 OM 的组合。** App 团队固定 App、Forge、Pi、配置及能力包，构建包含必要依赖的部署产物。运行时挂载 OM 和数据，注入 Secret。正常启动和 Turn 不自动追踪 latest 或安装新扩展。

发布清单记录实际软件/配置/资源身份、种子版本及持久化格式要求；不把当前 active OM 强行锁进 App 发布号。每次执行再记录实际选定的 OM 修订与工具快照，形成可解释的组合。

升级前检查配置、依赖、存储版本及当前 OM/业务任务所需能力。检查的是可运行性与兼容性，不是 WD 授权工具名单，不让 OM 编辑依赖 MCP 在线。具体业务方法的兼容通过契约和代表任务验证；静态检查不能证明任意专业方法都正确。

**I-12：软件回滚、OM 撤销、数据恢复是独立操作。** 升级前停止接收新任务、处理运行任务和未知命令、备份再迁移。声明存储迁移与旧版本支持范围。若数据库已不兼容，不能只换回旧镜像。回滚软件不会自动回退组织 OM，也不能抹掉 App 已发生的业务效果。

备份覆盖 OM 仓库/工作树、数据库、轨迹、原生 Pi 会话及工作文件，以及关联 App 的恢复点。凭据按独立 Secret 机制保存，短期 App token 不持久化。恢复演练在隔离目录进行，验证历史来源、个人/组织分支、未完成候选、旧 Work 和原业务回执；仅检查健康接口不算恢复成功。

迁移机器需处理 Git worktree 和原生会话绑定中的路径，不假定复制目录即可修复绝对路径。保持审计身份；不能通过选“最近会话”修补绑定。具体路径修复和迁移操作在实现时形成受验证的手册。

## 8. 验收与实施顺序

行为样例见 [App 集成验收场景](acceptance/app-integration.feature)。它是待实现的验收规格，不是自动化已通过的记录。

| 顺序 | 交付切片 / 责任边界 | 必须证明的结果 |
| --- | --- | --- |
| 1 | Forge 配置与资源适配器、App 发布配置 | 只读显式配置加载；原生包管理；缺失可诊断；不加载宿主个人资源；Work/Reflection 分离 |
| 2 | App 联调入口、Forge 本地执行与诊断 | 不构建 Docker 完成修改→运行→观察；版本可见；配置变化后接续；开发数据独立 |
| 3 | 通用阅读能力包、种子与用户 OM 治理 | PDF 工作方法迁出 OM；同一阅读能力用于不同领域；旧笔记可接续且不冒充事实；现有 OM 通过用户分支审查，不自动合并组织主分支 |
| 4 | App 身份/MCP/嵌入入口、Forge 用例 | 真实身份与对象绑定、草稿回执、拒绝、断连取消、未知结果恢复；不增加第二套授权 |
| 5 | 初始化与 OM 适配器、部署发布 | 空环境与重启幂等；新版种子不覆盖既有 OM；本地与镜像执行相同契约 |
| 6 | 发布、持久化与运维入口 | 组合兼容、升级备份、回滚限制、路径迁移和隔离恢复演练 |

先用本地模拟模型和合成资料验证协议、压缩恢复与写入语义，再做代表性真实资料验收；真实客户资料外发仍需授权。验收报告区分确定性工程结果、真实模型观察与专业人员接受，记录未完成项，不以文档完成冒充功能完成。

反馈效率记录从修改到观察生效所需步骤、重启服务和耗时；本轮不虚构秒级性能承诺。下一步实施需把各场景映射到实际测试、启动命令和发布演练记录。

## 9. 当前实现与差距（2026-10-23）

| 范围 | 已核对的现状 | 本需求要求补齐 |
| --- | --- | --- |
