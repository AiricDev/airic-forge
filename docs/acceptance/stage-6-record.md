# 阶段 6 验收记录：P1 组织 OM 管理

状态：组织 OM 管理的本机纵向切片已交付；真实业务效果和生产容量目标仍待真实部署建立样本。日期：2026-10-03。隔离服务：`http://127.0.0.1:4181/`，数据在 `/private/tmp/airicforge-p1-stage6-20261003`，与原 P0 实例分离。

本机演示可在启动 Forge API 时设置 `FORGE_ENABLE_TEST_IDENTITY_SWITCH=true`。此时服务只监听 `127.0.0.1`。仅原本以管理员账号登录的短期会话会显示顶部“测试身份”切换；切换后页面和 API 都按所选用户的权限运行，可在同一会话切回原管理员。退出、会话过期或服务重启即结束该测试链路。正式部署不设置此变量，切换接口返回 404。

## 已验证

- **P1-01～02，比较与选择性吸收：**管理员在工作台比较作者分支与 `main`，固定来源修订、理由和可分享证据，只勾选 `report-authoring/policy.md`。审阅对候选完整 OM 运行 WD/SK、文档引用、能力目录和路径检查。浏览器完成采纳后，`main` 为 `bd64c616b9e2afa22a387bab93fbd95b73cb2d4f`，原作者 HEAD 仍为 `111451fca72320366849c18c3ea2bb0ca19f2538`。组织提交包含贡献 ID、作者、来源修订、理由和基准 trailer；`method.md` 中作者的另一项改动未进入 `main`。最终界面展示的是实际吸收差异，见 [截图](stage-6-organization.jpg)。贡献来源修订另有 Git ref 固定，避免后续分支重写导致来源不可读取。
- **P1-03～05，成员自主同步与历史：**普通成员先看见 `main` 更新提示；同步生成独立 Proposal，采纳前个人 HEAD 未动。浏览器中重新校验、审阅并采纳后，个人 HEAD 为 `11cdd6371922978361d8baf13b3831062f414218`，其中含组织政策；界面改为“个人 OM 已包含当前组织版本”。真实 Git 测试覆盖个人与组织同路径冲突、手工编辑冲突内容、继续 rebase、再次审阅与采纳；旧个人 HEAD 留在第一父历史，可按旧 Turn 修订读取。`main` 若在审阅后变化，接受被拒绝。
- **P1-06，权限与数据边界：**普通用户可读 `main` 文件和历史，不能查看他人的 Work、贡献详情、组织比较或成效基线。仅选定 OM 文件进入组织 Git 提交，Session、轨迹、App token 和反馈保存在其原有私有存储中。HTTP 鉴权测试覆盖 401/403 路径。
- **P1-07，基线口径：**工作台加入用户 Work 反馈，分别记录必要人工判断、可避免纠正、知识确有帮助、结果正确/有误；管理员基线将 Work、Turn、Reflection、Proposal、组织贡献等活动量，与反馈数量分开显示，另计算已采纳提议和组织贡献的中位耗时。浏览器以作者身份录入一条“可避免纠正”，管理员基线显示该项为 1。此处是观察样本和自报反馈，不能据此断言 OM 已带来效果改善。具体改善比较仍需同 Work 类型、难度、能力目录与模型配置的真实样本。
- **P1-08，隔离容量与故障样本：**`scripts/p1-capacity.mjs` 在本机临时 SSD 目录生成 20 用户、100 Work、2001 条 JSONL 事件，执行 20 个并行读取请求，并模拟轨迹末尾截断及 SQLite/Git 重启恢复。本机一次运行的装载时间 801 ms、读取时间 1 ms，总 817 ms；20 个读请求由单进程执行，不能代表 20 个并发 Turn。尚未设置生产数值目标，也未做 CertReporter 联合负载或大规模故障测试。
- **回归：**Forge API 22/22、领域 8/8；生产前端 TypeScript 和 Vite 构建通过，`airicforge:p1-stage6` 本地 Docker 镜像构建成功。API 套件的本地监听测试在允许 loopback 的环境中通过。浏览器在独立服务实测组织吸收和成员同步，并在服务重启后重新读取已采纳记录；原 P0 实例没有用于阶段 6 写入。
