# AiricForge 产品需求

状态：当前产品基线。已实现与下一步需求分别记录，不以文档存在代表功能完成。完整 App 集成与交付要求见 [app-integration.md](app-integration.md)。

## 产品定义

Forge 是由业务 App 团队组装进运行环境的第三方 Agent 服务，提供嵌入式 Copilot、工作轨迹、个人及组织 Operating Model（OM）治理和 Reflection。组织能基于实践改进专业方法，无需每次修改代码和发布应用。

当前一个实例绑定一个 CertLab 和一个组织，支持多用户。任意 App 注册、多 App 平台和多进程执行不在当前实现范围。

产品闭环：在 App 中工作 → 留下可追溯证据 → 人工发起 Reflection → 准备私有 OM 草稿 → 作者确认提交 → 下一轮采用新修订 → 有选择地贡献给组织 → 组织审核合并 → 成员自行同步。

## 职责

| 所有者 | 内容 |
| --- | --- |
| App | 身份、业务事实、专业权限、命令事务、版本、资料和原始回执 |
| Forge | Work/Turn、来源、业务桥、检查点、审计、Reflection 和 OM 治理 |
| Pi 与通用能力包 | Agent 循环、会话、压缩、文件工具、大型 PDF 的分块理解、图文阅读和进度接续 |
| 组织 OM | 业务逻辑、专业方法、证据充分性、标准例外、责任与交接 |
| App 发布配置 | Forge/Agent 版本、扩展与依赖、服务连接和运行方式 |

OM 不维护分页、阅读笔记文件或压缩算法。业务状态、原始证据、模型会话和凭据不写入 OM。通用阅读与现有 OM 的内容分离仍属下一步交付要求。

## 工作与业务操作

- 用户经 App 验证进入 Copilot；Forge 校验组织、报告和 Work 所有权。页面状态只提供聚焦提示，App 返回权威上下文。
- 当前运行入口是 `report-authoring`；用户可选择既有 Work 继续，结束后的 Work 仍可阅读。报告关联、长期对话与每轮来源独立记录。
- 每 Turn 固定个人 OM HEAD、实际文档和当前用户 MCP 工具快照。工具动态发现，不需要 Forge 目录审批或 WD 工具白名单。
- App 每次重新判断用户、目标、业务版本与专业权限。Forge 管理员身份不授予 App 专业权限。
- 成功必须有原始业务回执。未知结果阻止后续写入，查询原命令结果，不能通过换命令 ID 重放。
- 检查点与反馈记录实际成果、未决事项和人工决定；它们不代替 App 的专业授权。
- 当前断开 ACP 会停止相关执行并撤销 App 会话；重新进入需认证，不默认成为后台自主任务。原生会话恢复不恢复业务授权。

## 原生 Agent 执行

Work 和 Reflection 使用 Pi 1.2.0 原生持久化会话、自动压缩、文件工具及显式 Skills/MCP/tool_search。没有第二套 Forge 摘要缓存或强制逐页笔记工具。

会话显式绑定组织、用户、Work/Reflection 及来源，来源变化创建新关联，保留旧会话和工作文件。笔记是可错的工作记忆，不是权威业务状态。当前本机原生工具具有进程权限，工作目录不承诺 OS 安全隔离。

当前仅加载随 Forge 发布的明确资源；App 版本化 Pi 配置、扩展身份装配和资源诊断尚待实施。详见 [原生执行契约](contracts/context-projection.md)。

## 个人 OM 与组织协作

- Git commit 是 OM 修订，个人 `users/<id>` HEAD 从下一轮生效；运行中的 Turn 和历史来源保持不变。
- 手动、组织同步及 Reflection 草稿是隔离 detached worktree 中未提交的文件。保存不改变 active，作者确认后校验并快进个人分支，丢弃不改变生效版本。
- 普通讨论不自动改 OM；用户明确要求可准备草稿，Lens 可选。Reflection 没有 App token，不能提交业务命令或自动采用修改。
- 无来源 Work 的独立 Reflection 不制造虚假业务记录；引用已有轨迹必须验证归属和事件来源。
- 组织贡献固定个人来源，按文件选择，以三方补丁追加提交；校验失败不发布，main 变化需重新准备，采纳创建合并提交。
- 贡献状态与所选内容从 Git 推导。成员主动同步组织更新并解决冲突，组织更新不覆盖个人内容。
- 管理员可读取有权管理的资源，不冒充作者提交个人 OM 或继续其 Reflection；组织治理权限与个人创作权限分开。
- API 建议是交付给 App 团队的需求，不能自行注册工具、安装扩展或更改业务权限。

当前操作与格式见 [OM](operating-model.md)、[个人 OM](personal-om-changes.md)、[用户管理](user-administration.md)。

## 交付与恢复

Docker 用于发布，本地源码开发需要无需 Docker build 的快速反馈。Agent 配置与扩展随代码管理，初始 OM 是版本化种子；生效 OM、会话和运行数据独立持久化。重启及新版种子不覆盖组织修改。

软件发布版本与 OM 修订分别演化，每次执行可追溯实际组合。升级需校验能力与存储兼容、处理在途任务并备份；软件回滚、OM 撤销和数据恢复分别处理。当前启动和存储边界见 [部署](deployment.md)与[恢复契约](contracts/persistence-and-recovery.md)，完整待实现流程见 [集成需求](app-integration.md)。

## 验收和范围

工程验收覆盖真实身份与 MCP、固定来源、权限拒绝、未知回执、会话恢复、压缩接续、私有草稿、组织合并和用户停用收尾。自动化使用临时数据库/仓库和模拟模型。真实资料外发需授权；真实草稿成功不等于专业结论已接受。

衡量可避免纠正、必要人工决定、任务结果和知识帮助，按可比任务观察改善。Work/提交/贡献数量仅为活动，不能证明能力提升。业务效果目标和容量数值以真实部署样本确定，当前未承诺数值。

不在本轮增加多 App/多租户平台、插件市场、自动采纳、新 Agent 框架、新 PDF 解析引擎或 OCR。下一步顺序见 [开发计划](development-plan.md)，行为验收见 [App 集成场景](acceptance/app-integration.feature)。
